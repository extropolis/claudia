# P0 "One Host" Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Exactly one Claudia backend per user, on any always-on host; every UI is a thin authenticated client; the whole installation can be exported, imported, and handed off between hosts.

**Architecture:** No new subsystems. The backend already serves its SPA and owns local PTYs; P0 adds instance identity, always-on auth, data-dir hygiene, attach mode for Electron, a minimal viewer model, and export/import with path remap. Every task is its own PR against `main`.

**Tech Stack:** Node/TypeScript (Express + ws + node-pty), React/Vite, Electron, vitest. Backend auto-reloads via `tsx watch` — never restart it, never touch ports 4001/5173.

**Spec:** `docs/plans/claudia-portable-backend-and-native-clients.md` (draft v3). Section numbers below refer to it.

## Global Constraints

- Every PR targets `main`; branch from `origin/main`, not from another feature branch.
- Tests alongside code, in `backend/src/__tests__/` (vitest). Integration temp dirs go under `homedir()`, never `os.tmpdir()` (macOS `/var` is blocklisted).
- `shared/` is aliased to source in vitest configs; run `npm test -w backend` / `-w frontend` / `-w shared`.
- No attribution lines in commits or PRs. Commit; do not push and do not open a PR until the user has validated.
- Coverage gates: per-file thresholds, repo-wide ratchet (`coverage-baseline.json`), 60% line floor on new files.
- Do not restart the dev server. Verify with `backend/test-cli.ts` where possible.
